# EverPlanet 연구 · 전투 보상과 상점 거래

2026년 10월 Godot 개발본. 8월 시제품에서 마을과 필드를 오가며 의뢰 하나를 마치는 흐름을 만든 뒤, 10월에는 전투에서 모은 재료를 제출하고 보상 장비를 착용하는 과정까지 연결했다. 아래는 AI 보조를 활용한 개인 연구 프로젝트의 게임 규칙과 당시 엔진 입력 시험 결과다.

## 의뢰 재료를 바닥에 둔 채 한 마리 더 잡으면

처치 수는 적을 쓰러뜨린 순간 반영한다. 수집 의뢰의 재료는 바닥에 떨어지고 플레이어가 주워야 소지품에 들어간다. 이때 가방에 든 수량만 세면 눈앞에 필요한 재료가 전부 떨어져 있어도 계속 같은 재료가 나온다. 수집 목표가 있는 의뢰에서는 가방에 든 수량과 바닥에 남은 수량을 합쳐 추가 드롭 여부를 결정했다.

`combat_controller.gd`의 `_needs_quest_drop`에서 발췌했다. `required`는 해당 의뢰에서 요구하는 수량이다.

```gdscript
var available := int(GameState.get_inventory().get(item_id,0))
for loot in get_tree().get_nodes_in_group("world_loot"):
	if not loot.collected and loot.item_id==item_id: available += loot.count
return available<required
```

## 같은 장비가 두 개 있고 한 개를 착용했다면

상점은 소지 수량에서 착용 수량을 뺀 만큼만 판매를 허용한다. 같은 검 두 자루 중 한 자루를 착용했다면 한 자루만 팔 수 있다. 구매할 때는 단가와 수량으로 총액을 계산하고 잔액과 보유 한도를 확인한다. 거래 버튼을 누른 순간 다시 견적을 계산해 화면을 열었을 때와 현재 소지품이 달라져도 현재 상태로 처리한다.

`game_state.gd`의 `_complete_shop_transaction`에서 거래 확정 직전의 처리를 발췌했다.

```gdscript
var quote := get_shop_quote(shop_id, item_id, count, operation)
if not bool(quote.ok):
	gameplay_message.emit(String(quote.message))
	return false
```

## 플레이와 재시작에서 확인한 결과

시험 도구가 Godot에 키를 누르고 떼는 입력을 보내 캐릭터를 움직이고 상점 버튼을 조작했다. 아래의 ‘재시작’은 게임 프로세스를 종료한 뒤 별도 시험 프로필의 저장 파일을 다시 불러온 실행이다.

| 시험 기록 | 플레이 중 확인 | 재시작 후 확인 | 통과한 검사 수 |
|---|---|---|---|
| `harbor-service-gpu-06` | 상점에서 3개를 한 번에 산 뒤 1개를 팔았다. 소지금과 수량 변화를 확인하고 착용 중인 검의 판매가 막히는지 검사했다. | 소지품, 착용 장비, 마지막 거래 내역과 잔액이 일치했다. | 플레이 30/30 · 재시작 17/17 |
| `b2-01` | 적 5마리를 처치하고 바닥의 재료를 주워 의뢰인에게 제출했다. 의뢰 보상으로 받은 신발의 표시와 방어력 반영도 확인했다. | 복귀 위치, 소지품, 신발 착용, 의뢰 완료와 보상 수령 기록이 유지됐다. 이미 마친 수집 행동도 다시 실행되지 않았다. | 플레이 25/25 · 재시작 9/9 |

검사 수에는 씬 진입과 저장 파일 작성 같은 실행 조건 확인도 포함한다. 전투 시험에서 직접 확인한 범위는 처치부터 재료 획득·제출·저장 복원까지다. 바닥에 일부러 재료를 남긴 상황의 추가 드롭 조건은 위 코드에서 확인할 수 있다.
