# FM26 시대별 데이터 · 과거 선수의 나이와 동명이인 처리

2005년 선수를 FM26에 옮길 때 실명만 유지하면 2005년 당시의 선수단을 구성하기 어렵다. 연도별 빌드는 선택한 시즌의 나이와 구단, 능력치를 기준으로 삼는다. 여러 시대의 선수를 한꺼번에 모으는 방식과 선택 연도 하나의 명단을 만드는 방식에는 서로 다른 규칙이 필요했다.

## 연도 하나를 선택한 경우

2005년의 나이를 2026년에 유지하기 위해 선수와 스태프의 생년을 21년 뒤로 옮긴다. 2010년 빌드라면 16년이다. 예를 들어 2005년에 쓰인 가상의 1985년생 기록은 같은 월·일의 2006년생으로 옮긴다. v6부터 연도 빌드에서는 그해의 구단과 능력치를 사용한다. 구단명이 풀리지 않으면 멀리 떨어진 다른 시즌의 소속팀으로 메우지 않고 미확정 목록에 남긴다.

## 같은 인물 ID가 가리킨 서로 다른 사람

선수와 스태프 자료가 겹친 13개 ID에서 현재 명단의 ID만 대조했을 때는 모두 동일인으로 보였다. 실제 XML을 만들 때 읽었던 과거 시즌 자료를 대조하자 7개는 다른 사람의 스태프 정보를 담고 있었다. 같은 이름으로 보인 한 사례는 선수 자료에는 1989년생, 과거 스태프 자료에는 1959년생으로 기록돼 있었다.

이 재검사로 잘못 합쳐진 속성 190개를 회수했다. 충돌 속성 54개 가운데 36개는 기존 선수 자료와 일치해 유지했고 18개는 다른 사람에게서 온 값이라 제외했다. 스태프 7명의 레코드 220개는 별도로 보관했다. 이들에게 새 FM26 ID를 연결하는 일은 보류 상태다.

**작업 근거**　xmlbuildcore 수정본의 연도 빌드 변경 기록, 2026년 11월 15일 속성 충돌 및 스태프 7명 재검증 기록. 최신 정정 결과를 적용했으며, 보관 자료로 전체 빌드를 다시 돌린 결과까지 포함하지 않는다.
